# Software Bill of Materials (Phase 29 Stage 4)

Secure Project MB is standard-library-only Python except for four
runtime packages, all lazily imported behind their own integration's
seam module (never a hard import at `secure/__init__.py` load time), so
a missing one degrades that one integration to `STATUS_UNAVAILABLE`
rather than breaking the app. One further package is dev-only.

| Package | Minimum version pinned | License | Why it's here | Import boundary |
|---|---|---|---|---|
| `bleak` | 3.0.2 | MIT | Live BLE peripheral discovery — no stdlib way to do this on macOS (Phase 9). | `secure/bluetooth/ble/scanner.py` |
| `pyobjc-framework-CoreBluetooth` | 12.2.2 | MIT | Synchronous Bluetooth powered-on/authorization state read that `bleak` doesn't cleanly expose (Phase 9). | `secure/bluetooth/ble/state.py` |
| `yara-x` | 0.13.0 | BSD-3-Clause | YARA-style content-pattern matching — no stdlib equivalent (Phase 16). | `secure/integrations/yarax/_engine.py` |
| `PyYAML` | 6.0.3 | MIT | Parses Sigma detection rules (YAML documents) via `yaml.safe_load` only, never `yaml.load` — rule files are untrusted data (Phase 17). | `secure/integrations/sigma/_yaml.py` |
| `pytest` | 7.0 | MIT | Dev-only: runs this project's own 1,542-test suite. Never imported by `secure/` itself — `secure/ai/verify/operations.py`'s `run_pytest` operation *shells out* to it as a subprocess, it doesn't import it. | N/A (dev/test only) |

## What's deliberately absent

Every other capability in the app — SQLite storage, JSON/logging,
osquery/Suricata/Zeek/Velociraptor integration (all three read the
target tool's own output/log files or shell out to `-V`/`--version`
only, no client library), VirusTotal's REST API (via
`urllib.request`), and the two local AI provider backends (Ollama and
any OpenAI-compatible server, both via plain HTTP over
`urllib.request`) — uses the Python standard library alone. This is a
deliberate project-wide discipline (see `requirements.txt`'s own
per-dependency justification comments), not an oversight, and it's why
this SBOM has five rows instead of fifty.

## Provenance note

`bleak` and `PyYAML`'s versions were confirmed by a real install and
import in earlier phases' own build sandboxes (see PROJECT_NOTES.md's
Phase 9 and Phase 17 change-log entries and `scripts/
ble_stepzero_check.py`). `yara-x` and `pyobjc-framework-CoreBluetooth`'s
minimum versions are the packages' documented stable releases as of
the phase that introduced them, not independently re-verified by a
fresh install in this phase's own sandbox (which has no network
access) — confirm on the actual target Mac before relying on either,
the same "step-zero proof-of-concept first" discipline BLE's own
rollout used.

## Keeping this current

This file is generated by hand, not by an automated SBOM tool (no
`pip-audit`/`cyclonedx-py`/similar is part of this project's own
toolchain). Update it whenever `requirements.txt` gains or loses an
entry — the two files should never disagree about what's a runtime
dependency.
